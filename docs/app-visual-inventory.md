# App visual inventory

**Scope and yardstick:** source-level inventory of app surface wiring at `origin/main` `f7d3ca1`, measured 2026-10-25. I traced the PWA static route table, each HTML screen's direct CSS/script/icon references, CSS image URLs, and file introduction commits with `git log --follow --diff-filter=A`. This is not a browser-rendering or device measurement: live service-worker delivery, current browser rendering, and physical-device appearance are `NO_DATA` because they were not exercised for this piece.

The PWA shell has at least three simultaneously present visual systems: the newly introduced face, the older command dashboard in system-colored minimal mode, and the separate white/purple tabbed command app. The creation reader and privacy mock add two smaller independent treatments. A shared icon set exists for browser installation, but the in-screen controls do not share a common icon component: the face draws canvas icons, the dashboard has inline SVG, and the command app combines HTML controls with an externally fetched compass SVG.

The command-app document declares `lang="en"`, while some initial tab labels and help strings are Spanish and are translated at runtime. Its visible language on a particular install was not tested here. This is a source-level language/style-era mismatch, not a rendering claim.

## Adoption impact by screen group

This analysis is based on CSS/source wiring, not on a live DOM computed-style dump.

| Screen group | What changes could affect it | Risk if legacy properties are replaced before migration |
|---|---|---|
| Face trio | `--bg`, `--fg`, `--panel`, `--accent`, `--edge`, `--r`, `--bw`, `--gap`, `--tap`, `--joy`, `--icon`, plus per-layout overrides. | Highest cross-screen coupling: a base token affects all three skins, while skin overrides intentionally alter layout, tap sizes, and borders. Replacing the names or semantics can erase these variants or reduce touch targets. |
| Command app | Local ink/paper/ground/line/status/accent/halo/radius values and its dark-mode overrides. | High: every tab shares `app.css`; a palette or type change reaches conversation, boundary, notebook, tools, and settings at once. |
| Dashboard and console | Browser-native `Canvas`/`CanvasText`, `GrayText`, focus highlight, and unique `consola.css` rules. | Medium: it will not respond to a new token package until explicitly migrated. Resetting native colors can harm system-theme contrast; console styles do not inherit the app palette today. |
| Creation reader | Inline hardcoded page colors, spacing, and typography. | Low code coupling, but it will remain visually distinct until its embedded style is migrated. |
| Privacy prototype | The duplicated semantic variables and four-state examples. | Lowest adoption cost and useful as a token-contract fixture, but it is not a shipped screen. |

No stylesheet was changed and no rendered screen was claimed as measured in this inventory.
