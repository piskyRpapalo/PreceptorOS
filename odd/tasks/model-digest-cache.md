# Bounded digest cache for local models

PROPUESTA · REQUIERE_FIRMA. Stacked on app #137 (`f3d7cc9`). The existing verifier `consola.py:163` keys cached hashes by path, device, inode, size, modification time and change time, but clears the entire cache whenever another blob is measured (`:188`). The lab model listing verifies the code candidate (`lab.py:244`), and the new mini inference gate verifies the mini, so alternating them evicts both. One synthetic RAG and one chat call on the rack each took about 23 seconds including selection, hashing, startup and inference (app #137 receipt); this is not proof that hashing caused the latency.

Slice: keep a bounded set of eight cached identities, evict the oldest, and remove stale identities for the same path. Re-stat before every lookup; changed bytes with changed file identity or metadata must be rehashed and a mismatch rejected. The cache is a speed optimization, not authentication, a signature, or race-free file loading. No new network and no model promotion. A controlled rack before/after timing is required; semantic model quality and fleet performance are NO_DATA.
