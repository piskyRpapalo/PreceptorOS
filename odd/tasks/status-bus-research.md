# Status bus: post-MVP-1 research proposal

Scope: a future local, read-only status bus for the map. This is a design note, not a transport, deployment or claim that any agent is live.

Two reference observations, read 2026-10-28: [adapter contract at commit 8cd9d76](https://github.com/Station-Sciences/bot-crossing/blob/8cd9d76b3bf5eddaec7d4ba88f0d1c0547a312dc/server/harnesses/README.md) describes per-source detection and scanning, unique IDs, read-only source access, and isolation when an adapter fails. Its status fields are observations; the adapter notes also warn that a process alone does not prove work. [Runtime README at commit 8e83119](https://github.com/androoAGI/starnet/blob/8e8311987eaf2ddc49cfc1e31f2dc3a7dcba3bec/README.md) describes a local authority whose front end consumes the same runtime events, with secrets kept outside the front end. These are source descriptions, not independent tests of either system.

Proposed house boundary: each local adapter supplies bounded, typed observations `{id, state, cause, source, sequence}`; the local authority validates IDs, sequence and size, preserves a cause for unavailable or invalid data, and publishes a snapshot to the renderer. Allowed semantic states and their precedence must be defined from measured house contracts, not guessed from logs. The renderer consumes that snapshot plus an explicit game cycle and produces frames; it neither infers work from animation nor executes a service. A missing or failed source becomes NO_DATA/STALE with cause, and absent live nodes do not appear. Reuse the landed colony state, projection and poll contracts where applicable.

Keep raw prompts, paths, credentials and model output out of the public visual packet. Make reading a status and taking an action separate; the human gesture and existing signature gates remain authoritative. A bounded queue or snapshot should declare loss and overflow rather than fabricate completion. No persistence, external upload, reward, signature or action is implied by this proposal.

Open measurements: authoritative sources and identity trust, observation freshness, transport and backpressure, restart ordering, source revocation, device motion and frame size. All are NO_DATA until implemented and measured. Suggested judges: malformed records, duplicated IDs, source failure, out-of-order sequence, missing cause and stale observation; same input snapshot and cycle must yield the same serialized frame twice. Before/after capture is NO_DATA: no visual or runtime change is proposed.
